# 🚗 Smart EV Charging Station Analytics System

A production-style **data analytics capstone** (no ML) built entirely with
**Python, NumPy, Pandas, Matplotlib, Seaborn, MySQL, and Streamlit** —
covering every topic in your syllabus screenshots.

Business problem it solves:

> *Which charging stations are performing well, when is demand highest, which
> chargers generate the most revenue, where are customers waiting too long,
> and where should the company add capacity?*

## 2. The Dataset

Seven relational tables, generated with NumPy/Pandas (no external downloads),
simulating one year (2025) of operations across **20 stations** in Delhi NCR:

| Table                    | Rows    | Description                                   |
|---------------------------|---------|------------------------------------------------|
| `stations.csv`             | 20      | Station name, city, coordinates, charger count |
| `chargers.csv`              | 131     | AC/DC/DC_FAST chargers per station              |
| `customers.csv`             | 5,000   | Individual / Fleet customers                    |
| `vehicles.csv`               | 8,000   | Vehicle type, model, battery capacity           |
| `charging_sessions.csv`      | 60,300  | **Main fact table** — every charging session    |
| `queue_logs.csv`              | 19,200  | Hourly queue snapshots per station              |
| `electricity_cost.csv`        | 7,189   | Daily electricity consumption & cost per station |

Realistic messiness was deliberately injected into `charging_sessions.csv`
(~2% nulls in 3 columns, ~0.5% duplicate rows, a handful of impossible
negative-duration rows) so the Pandas cleaning stage has genuine work to do —
exactly like a real production dataset.

After cleaning + merging, the analysis-ready file is:
**`data/processed/ev_sessions_clean.csv`** (59,985 rows × 32 columns).

## 3. How To Run It Yourself

```bash
# 1. Set up environment
conda create -n ev_analytics python=3.11
conda activate ev_analytics
pip install numpy pandas matplotlib seaborn sqlalchemy pymysql streamlit

# 2. Generate the raw dataset
python src/generate_data.py

# 3. Clean, engineer features, and merge tables
python src/clean_data.py

# 4. Run EDA + business analytics (creates 10 charts in /charts)
python src/eda_business_analysis.py

# 5. (Optional) Load into MySQL
mysql -u root -p < sql/01_schema.sql
mysql -u root -p --local-infile=1 ev_charging < sql/02_load_data.sql
mysql -u root -p ev_charging < sql/03_business_queries.sql

# 6. Launch the interactive dashboard
streamlit run dashboard/app.py
```

## 4. Business Questions Answered

| Category        | Example Question                                      | Where |
|------------------|----------------------------------------------------------|-------|
| Revenue           | Which station/charger type earns the most?               | `03_business_queries.sql` § A, dashboard Page 5 |
| Customers          | Who are the top spenders? What's the segment mix?          | § B, dashboard Page 4 |
| Chargers            | Which chargers are underutilized?                          | § C, dashboard Page 3 |
| Stations             | What are the peak hours? Busiest stations?                  | § D, dashboard Page 2 |
| Queueing               | When is the wait time longest?                               | § E |
| Profitability            | Revenue − electricity cost = gross margin, by station          | § F, dashboard Page 5 |
| Time patterns               | Weekday vs weekend, day-of-week revenue                          | § G |

**Customer segmentation** (Occasional / Regular / Power User) is done with
plain rule-based logic (`.apply()` in Pandas, `CASE` in SQL) — **no clustering,
no ML** — exactly as requested.

3. **Live demo** of `streamlit run dashboard/app.py` — walk through all 5 pages.
4. **3–4 of the strongest charts** from `/charts` (correlation heatmap,

5. **2–3 SQL queries live** in MySQL Workbench — the subquery and CASE-based

6. **Close with a business recommendation**, e.g. "Station X has the highest
   utilization but the lowest charger count — recommend adding 2 DC Fast
   chargers there," backed directly by your `station_summary.csv` output.

## 7. Extending It Later

If you ever want to add the ML layer back in, this dataset already has
everything needed — `charging_duration_minutes` (regression target),
a `completed_on_time`-style flag can be engineered from `queue_logs`, and
`charger_type` is a ready-made classification target. But as built, this
project is 100% ML-free, exactly as requested.
